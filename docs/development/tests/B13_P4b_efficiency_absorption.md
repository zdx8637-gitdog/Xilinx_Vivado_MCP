## 0. 目标与观测指标

**目标**：白盒（及黑盒）从任务书发出到全部门禁机器判定，用**最少的代际数、最少
的墙钟时间、最少的 token** 跑通。跑通的定义不变：gate 判据全部机器验证通过。

**观测指标（尽量机读）**：

| 编号 | 指标 | 定义 | 数据源 |
|---|---|---|---|
| M1 | 代际数 | 任务书续写次数（WB_PROMPT + CONTINUE 代数） | 任务书文件计数 |
| M2 | 重做条目数 | 按文档二 20 类登记的"写错→改回"条目数 | evidence/FINDINGS.md 重做台账 |
| M3 | 墙钟时间 | 任务书发出 → 最后 gate 判定落盘 | 文件时间戳 |
| M4 | token 总量 | runner 会话用量（框架侧不可直读，记为外部指标） | 运行器遥测 |
| M5 | 一次通过率 | 每个 gate 首次执行即 PASS 的比例 | gate_*_final.json 与重跑次数 |

M4 无法从框架侧机读，以 M1/M2/M3/M5 为主指标；M5 的"重跑次数"可由 gate 证据
文件的 *_r2/_r3/... 后缀机读计数。

   语义、tcpwnd_size_t u16 截断、tcp_write COPY 标志、SG BD 写序……每一处都是一轮
   改代码→重编译→重部署；
3. **已知坑反复诊断**：F-25 排空停滞一轮的诊断链，目录里留下 probe_drain_dbg ×5、

结论：**token 大头不在"正常流程"，在"写错重做"与"已知坑重复诊断"**。吸收目标
