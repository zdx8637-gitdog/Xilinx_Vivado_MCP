## 3. 立项三：ps_bsp_grep（BSP 真值源查询工具）

### 3.1 定位

PS 域**只读查询工具**：按模式检索本会话 BSP 的驱动头文件/生成头/实现源码，
返回函数声明、宏、结构体与上下文——机器可查的"正确库引用"，版本永远等于
本工程实际编译的库。

### 3.2 规格

| 项 | 规格 |
|---|---|
| 名称 | `ps_bsp_grep`（PS 域，与 `ps_*` 一致需显式 `session_id`） |
| 参数 | `session_id`（必填）；`pattern`（必填，子串或正则）；`scope`（可选：`headers` / `sources` / `all`，默认 `all`）；`max_hits`（可选，默认 50，有界上限）；`context_lines`（可选，默认 2） |
| 检索范围 | 会话 BSP 目录：`include/`（生成头，含外设参数头）+ `libsrc/`（`<驱动>_v*/src/` 头与实现源码）；排除二进制产物 |
| 返回 | `hits: [{file, line, text, context}]` + `total_hits` + `truncated` 标志 |
| fail-closed | BSP 不存在/未创建 → 明确错误（`BSP_NOT_FOUND`），**不得静默返回空**；无匹配 → `hits=[]` 与 `BSP_NOT_FOUND` 语义严格区分 |
| 只读性 | 不修改任何文件、不发布 Manifest、不进 Ledger 状态突变（query tool，同 `verify_consistency` 形态，不走 command→operation 状态机） |
| 泛化性 | BSP 是 `ps_create_bsp` 的通用产物，任何 Zynq 工程都有；工具零项目词 |

### 3.3 测试与验收

1. **单元**：临时目录构造假 BSP（include/ + libsrc/ 样例头/源）验证匹配、scope
   过滤、max_hits/truncated、BSP_NOT_FOUND vs 空结果；
2. **契约**：MCP SDK contract 测试（query 返回结构、参数校验错误码）；
3. **机械**：工具注册进 capabilities 表（109→110，`DOMAIN_APIS_IMPLEMENTED`
   机械派生计数同步更新）；跑 `test_o6_skill_contract.py` 全绿；
4. **真实路径（host_live）**：真实会话创建 BSP 后 grep 外设参数头验证基址宏
   与生成头一致；
5. **回归**：全量 `python -m pytest mcps` 报告 collected/passed 原始统计；
6. **验收口径**：下一次白盒任务书写固件时，用该工具查询的 API 引用与 BSP 头
   文件逐字一致（效率指标 M2 挂钩，判据：任务书执行中"凭记忆写 API"重做条目 = 0）。

## 4. 立项四：响应附注机制（已知坑运行时指引）

### 4.1 定位

MCP server **响应装配层**机制：工具响应命中已知症状关键词时，在响应独立字段
追加一条附注（已知问题编号 + 一句话处理建议 + 证据引用）。**只附注、不自动
修复、不改变工具执行**——暴露纪律不变，判断权仍在智能体。

### 4.2 规格

| 项 | 规格 |
|---|---|
| 数据源（两层） | **通用层**：`mcps/common/hints/known_issues.json`（机器可读版已知坑表，与 Skill §13/§14 同源维护，回流时同步更新 + 一致性测试）；**项目层**：`<PROJECT_PATH>/evidence/hints.json`（白盒发现即落盘，**即写即生效**，本会话下一次同类症状即带出） |
| 条目必填字段 | `symptom_pattern`（正则，大小写不敏感）、`advice`（一句话处理建议）、`source_ref`（§13.N 或项目 F 编号/证据路径）、`added_at` |
| 匹配与输出 | 工具响应文本命中任一 `symptom_pattern` → 响应对象新增独立字段 `annotations: [{hint_id, advice, source_ref}]`（上限 N 条）。**附注绝不混入被解析的输出文本**（result/uart_text 等原始字段保持原样——防 stdout 协议污染，与 F-06 同族教训） |
| 自更新 | 项目层：每次调用时读取，编辑即生效，无需重启；通用层：受控回流（过泛化滤网 + 批准），不允许智能体自主改框架资产 |
| 语义红线 | 附注不影响任何判定：verdict/校验/门禁全部仍以原始输出为准 |

### 4.3 测试与验收

1. **单元**：关键词匹配（含大小写/多命中/上限）、原始字段不变断言、条目格式
   非法即失败；
2. **格式门禁**：测试扫描两层 hints 文件的必填字段，烂账条目报错；
3. **契约**：响应含 annotations 字段的 SDK 测试；无命中时字段为空或缺失的约定；
4. **回归**：全量 pytest 原始统计；`test_o6_skill_contract.py` 全绿（通用层 hints
   同受泛化红线约束）；
5. **验收口径**：白盒撞已知坑时响应带附注；新坑落盘后第二次调用即带出（自
   更新生效）；效率指标 M3/M5 挂钩（已知坑诊断轮次降为 1 次查询）。
