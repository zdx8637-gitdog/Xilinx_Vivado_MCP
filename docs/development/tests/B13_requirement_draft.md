## 1. 目标与边界

| 侧 | 职责 | 不负责 |
|----|------|--------|
| 下位机（FPGA+PS） | 按指令采集**固定数据量**并边采边传（扫描上传模拟）；UART 收指令/打调试日志 | 图像排列、显示 |
| 上位机测试程序（PC，另派智能体） | 发"开始采集"等简单指令、接收数据、**解析并显示**（5000×5000 灰度图）、完整性对账 | 采集控制细节 |

- **采样率三档**：2k / 100k / 1M SPS，由 START 指令参数选择。
- **采集 = 固定数据量**：一次采集 = **5000 行 × 5000 点 = 25,000,000 个数据点
  = 50,000,000 字节（50 MB）**；每个数据点 = 1 个 16-bit 有符号样本
  （**ADC 的 CH6 通道**，二进制补码原始计数）。PL 按点计数精确截断，采满
  自动停止，传输被动（边采边传，采完传完）。1M 档一张图 = 25 秒。
- **帧尺寸约定参照 WaterBear**：其最宽 ROI 行 = 5000 点；本档约定
  **一行 = 一个上行数据帧 = 5000 点 = 10,000 字节 payload**。
- **采集引擎能力（8 通道 1 MSPS 压榨）**：AD7606C 为 8 通道同时转换，引擎按
  1 MSPS 采全 8 通道（L2 事件计数验收：CONV=BUSYF=1M/s、RD=8M/s、
  FRSTD=1M/s），**上行只传 CH6**（2 MB/s = 16 Mbit/s）。
- **覆盖式**：每次 START 从头覆盖写缓冲，不保留上一次采集（见 §5）。

## 3. 下行协议（UART，PC → PS，115200，8N1）

| 字段 | 长度 | 说明 |
|------|------|------|
| MAGIC | 2B | `0xA5 0x5A` |
| CMD | 1B | 指令码 |
| LEN | 1B | payload 字节数（0..16） |
| PAYLOAD | ≤16B | 参数（大端） |
| CRC16 | 2B | 全帧 CRC16-CCITT（**CCITT-FALSE 变体，见下方钉死定义**） |

**CRC16 钉死定义（避免变体歧义）**：采用 **CRC16-CCITT-FALSE**——
多项式 `0x1021`、初值 `0xFFFF`、**不反射输入/输出**、无最终异或；
计算范围 = 从 MAGIC 首字节到 PAYLOAD 末字节（**不含 CRC 字段本身**）；
传输字节序 = **小端（低字节在前）**。参考校验向量：字符串 `"123456789"`
→ `0x29B1`（用于上位机/下位机自测对照）。

每条指令应答 `ACK`（含结果参数）或 `NAK`（含原因码）；非法帧 → NAK 并继续；
超时 1 s 重发 1 次。

| CMD | 名称 | PAYLOAD | ACK 内容 |
|-----|------|---------|----------|
| 0x01 | START | 档位(1B: 0=2k,1=100k,2=1M) + 行数(4B, 默认 5000) + 点流模式(1B: 0=TPG, 1=ADC-CH6) + 保留(4B) | 实际 CONVST 频率 + 生效确认 |
| 0x02 | STOP | — | 已采点数 |
| 0x03 | STATUS | — | 状态包（§4.4） |
| 0x04 | SELFTEST | — | SELFTEST 判定块（BUILD/PL/PS） |
| 0x05 | PING | — | PONG |

- START 在上次采集未结束时收到 → NAK(BUSY)；采集结束自动回 IDLE。
- 点流模式：`TPG` = 内部测试图案（L1 自检/全速打流）；`ADC-CH6` = CH6 的
  16-bit 样本流。

### 3.1 应答帧线格式（PS → PC，UART；2026-09-01 真板实测钉死）

| 字段 | 长度 | 说明 |
|------|------|------|
| MAGIC | 2B | `0xA5 0x5A` |
| CMD' | 1B | ACK = 原命令 `\|` 0x80；NAK = `0x00` |
| LEN | 1B | payload 字节数 |
| PAYLOAD | ≤22B | ACK = 结果参数（大端，见下表）；NAK = `[reason(1B)]` |
| CRC16 | 2B | 与下行帧同算法同范围同字节序（CCITT-FALSE，MAGIC..PAYLOAD，小端） |

NAK 原因码（真板固件实际取值）：

| reason | 含义 |
|--------|------|
| 0x01 | BUSY（上次采集未结束） |
| 0x02 | CRC 错 |
| 0x03 | MAGIC 错 |
| 0x04 | 未知命令 |
| 0x05 | LEN 错 |
| 0x06 | 参数错 |
| 0x07 | 客户端未连接（NOT_READY；START 要求 TCP 已连） |

ACK payload（各命令）：

| 命令 | ACK payload |
|------|-------------|
| PING | `PONG`（4B ASCII） |
| START | 实际 CONVST 频率 Hz（4B 大端）+ 生效确认 `0xA5`（例：1M 档 `00 0F 42 40 A5`） |
| STOP | 已采点数（4B 大端） |
| STATUS | 状态包 22B（§4.4 同格式） |
| SELFTEST | ASCII 判定摘要 ≤16B（以 `L1=` 开头；完整判定文本经 UART 文本流输出，不在帧内） |

真板实测 KAT（上位机单测向量）：

- PING ACK `A5 5A 85 04 50 4F 4E 47` → CRC16=0xAAD0，传输 LE `D0 AA`
- NAK(CRC 错) `A5 5A 00 01 02` → CRC16=0x16DC，传输 LE `DC 16`
- START ACK(1M) `A5 5A 81 05 00 0F 42 40 A5` → CRC16=0x32D1，传输 LE `D1 32`

**帧尾 ASCII 调试文本**：真板在应答帧 CRC 之后输出一行 ASCII 调试文本（如
`B13 CMD START MODE=2 LINES=5000 STREAM=0\r\n`）；SELFTEST 的判定文本流在 ACK 帧
之前输出。**调试文本不属于帧**——上位机解析器必须按 MAGIC 扫描定位帧、忽略
帧外字节（读到 `A5 5A` 起算，按 LEN 取 payload + 2B CRC，帧外字节丢弃至下一个
`A5 5A`）。

## 4. 上行数据协议（TCP，PS → PC）

### 4.1 连接模型与静态 IP 约定

- **PS = TCP Server**（端口 **5001**）；**PC = Client 主动连接**。
- **网线直连 + 静态 IP 约定**：PS = `192.168.1.10/24`，PC = `192.168.1.20/24`
  （网关/掩码按直连习惯：掩码 255.255.255.0，无网关）。
- 连接建立后 PS 先发一帧 `READY`（版本 + 能力 + BUILD/PL/PS 标识）。
- **断线可重连，语义钉死**：PS 保持 Server 监听；重连后**继续发送尚未发送的
  行**（发送游标不因断连重置）。若断连期间发送游标被写指针追越（缓冲覆盖），
  被覆盖部分计入溢出计数并在状态帧告警，发送从"写指针 − 安全余量"处继续。
  上位机侧：断连提示明确、可重连、重连后按 SEQ 续拼（缺行按丢行计）。

### 4.2 帧格式（大端）

| 字段 | 长度 | 说明 |
|------|------|------|
| MAGIC | 4B | `0xB1 0x3A 0x00 0x01` |
| TYPE | 1B | `0x01`=数据行 `0x02`=状态/事件 `0x03`=READY/自检结果 |
| VER | 1B | 协议版本（当前 `0x04`） |
| SEQ | 4B | 行号（**0..行数-1，一张图内递增；新采集从 0 重计**） |
| LEN | 2B | payload 字节数 |
| CRC32 | 4B | 全帧（含头）校验；算法 = IEEE 802.3（`zlib.crc32` 同款），传输**大端**。**覆盖范围（2026-09-03 真板实测钉死）**：MAGIC..LEN（头 12B）+ **CRC 字段位置零参与**（4B）+ PAYLOAD——即把 CRC 字段补 4 个零字节后整帧连续计算（与下位机接收器同口径）。真板 KAT：READY 帧头 `B1 3A 00 01 03 04 00 00 00 00 00 60` + 96B payload → CRC32=`54 AC FE 90`（大端） |
| PAYLOAD | — | 见下 |

### 4.3 数据行帧（TYPE=0x01）—— 一帧 = 一行

- **payload = 5000 点 = 10,000 字节**（CH6 的 16-bit 有符号样本，大端）。
- 点序 = 采样时间序（TPG 模式为图案序）。
- 一张图 = **5000 帧**（SEQ 0..4999）；行数参数非 5000 时末行按实际点数发
  （LEN 表达真实长度）。
- 上位机收到帧即按 SEQ 拼 5000×5000 灰度图（显示降采样）。

### 4.4 状态/事件帧（TYPE=0x02）

payload = `{已采点数(4B), CONVST计数(4B), 水位(2B), 溢出计数(2B),
速率实测(4B, Hz), 看门狗错误(2B), 保留(4B)}`，**恒 22 字节**。保留(4B) 的
**首字节 = END 标志**（`0x00`=进行中 / `0x01`=采集完成）。STATUS 应答与周期
上报共用本格式；**采集完成时由下位机主动发 END 状态帧（TYPE=0x02、保留[0]=0x01）**。
上位机完成判据 = 收满 START 行数 **或** 收到 END 状态帧（双判据，先到者生效）。

### 4.5 完整性（DCC 口径）

- 行 SEQ 连续 + 帧 CRC32 + 行内点数恒 5000（末行除外）；上位机机读统计：
  `{总行数, 丢行, 错行, 首错SEQ, 吞吐}`；
- **溢出策略（放松）**：TCP 拥塞至缓冲满 → 丢最旧 + 溢出计数++ 并在状态帧
  告警；正常工况目标 0 溢出（2 MB/s ≪ GEM/TCP 能力，余量很大）。

## 5. 缓存与数据流（下位机）

- 三级缓冲：PL 采集侧**跨时钟异步 FIFO**（`xpm_fifo_async`，采集时钟域 →
  AXI-Stream 域，深度按背压预算选，建议 ≥4096 采样点；官方参考深度 1024）→
  **DDR3 覆盖式单缓冲（50 MB = 恰好一张图 25M 点）**→ lwIP 发送窗口。
- **数据搬运采用官方 AXI DMA（SG 模式）**（厂商已验证 IP，参照官方案例
  `course_s2_vitis/20_ad7606_sg_dma_hdmi` 与 `31_ad7606_lwip`）：PL 采集 →
  FIFO →（`axis_register_slice`，HAS_TLAST=1，官方 BD 同款）→ AXI DMA S2MM →
  DDR3；PS 用 XAxiDma 驱动 + 描述符环。备选：手写 AXI master 直写（参照
  另一工程师 aq_axi_master 思路），需自担完整验证。
- **FIFO 必要性（与官方一致）**：① ADC 数据为突发流（每帧转换完成后 8 通道
  突发、转换期空闲）→ FIFO 平滑成连续 AXI-Stream；② 采集域与 DMA S2MM/HP
  域跨时钟 → 必须异步 FIFO；③ DMA `tready` 因 DDR 仲裁/互连拥塞拉低时 FIFO
  吸收背压、采集不丢；④ 攒量使 DMA 突发高效。
- PS 按行组帧（零拷贝 `tcp_write` + 校验和卸载）；水位/点计数经寄存器暴露。
- 单缓冲语义：DMA 从缓冲头顺序写满 50MB（一张图），PS 随写随发（边采边传）。
- 一致性：DMA/PS 访问用 non-cached 段或显式 cache 操作。
- **覆盖式**：缓冲只服务当前一次采集；START 后从 0 覆盖写。
- 发送线程独立；UART 调试线程只打日志，不进数据面。

   1 MSPS 实时传输数据"的最终路径；
5. 上位机 GUI 联调时跑**同一套 DCC 统计**（§4.5），与接收器口径一致，仅多一层
