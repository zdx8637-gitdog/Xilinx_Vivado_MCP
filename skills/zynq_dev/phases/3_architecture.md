# S3 — 架构选型（Architecture Selection）

> 输入: 预算 + 板卡物理事实 | 输出: 拓扑 / 流协议草案 / 地址规划（全部占位符）

## 职责

做出**全部工程决策**：通信拓扑（走哪个高速口、数据通路形态）、时钟域划分、
缓冲深度、中断 vs 轮询、地址规划。本阶段输出的是「为什么这样连」的决策记录，
不产生 EDA 副作用。

## 输出（占位符形态）

| 决策项 | 占位符 | 说明 |
|--------|--------|------|
| 通信拓扑 | `<ARCH_TOPOLOGY>` | 接口选择、数据通路、时钟域 |
| 流协议草案 | `<ARCH_PROTOCOL>` | 帧格式、握手、打包方式 |
| 地址规划 | `<ARCH_ADDRESS_MAP>` | 各外设段基地址（S5 `platform_set_address` 用） |
| 同步策略 | `<ARCH_SYNC>` | 中断 vs 轮询、FIFO 深度、复位策略 |

## 智能体自主决策范围

- **全部工程决策**（Skill 决定「为什么这样连」）；
- 选型自检：对照 S2 预算逐项核对。

## 用户必须提供的物理事实

- 无（除非涉及板级改动，则回 S1 更新物理事实）。

## 失败恢复入口

| 症状 | 动作 |
|------|------|
| 选型自检失败（超预算/超资源） | 回 S2 调整预算假设 |
| 涉及板级改动 | 回 S1 与用户确认物理事实 |

## 涉及的工具类别

- domain query（只读证据）：`platform_list_ips`（BD 可例化 IP 清单）、`pl_query_*`、
  `ps_read_elf_info`、`ps_get_bsp_status`；
- 无任何 command / set 副作用。
